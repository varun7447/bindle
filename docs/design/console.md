# Console design

Goals, from user feedback on the first version: it looked basic, had too many tabs (six), and didn't help people quickly understand what they were looking at.

## What we looked at

- **Datadog LLM Observability:** a flame graph per trace and an out-of-the-box "operational insights" dashboard aimed at fast triage.
- **Langfuse** and **Arize Phoenix:** a span tree with a detail panel, sessions, scores and dashboards.
- **Error trackers (issues, grouped):** the same failure appearing many times becomes one row with a count and the latest example.

All of them show the data well; none answers "is anything wrong, and what should I open first?" in plain words. That is what this redesign adds.

## Principles

1. **Answer first, data second.** Every page starts with a sentence: the Home banner ("2 issues need attention · 30 runs from 3 agents, 20% failed …") and the run summary on the trace page ("refund-agent failed after 253 ms.").
2. **Group, rank, link.** Failures are grouped by step with a count and the latest error; agents with a high failure rate and runaway loops join the same list, most severe first. Each row links to exactly the run or step to open.
3. **Compare with something.** Key numbers show the change against the previous period, colored by whether it's good news, with the direction in an arrow and text (never color alone).
4. **Explain terms in place.** "Run", "p95", "failure rate" and "cost" carry a `?` with a one-sentence definition.
5. **Fewer places to look.** Three sections (Home, Runs, Alerts) and Settings (connect, keys, SDK settings as tabs). `⌘K` jumps anywhere, including a pasted trace ID.
6. **Deterministic explanations.** Summaries are computed from the trace (counts, failures, retries, repeated tools, leaf-step time), not generated by a model, so they are fast, free and never invent facts.

## Information architecture

| Before | After |
|---|---|
| Overview, Runs, Alerts, Connect an agent, Ingest keys, SDK settings | **Home**, **Runs**, **Alerts**, **Settings** (Connect · Ingest keys · SDK settings) |
| Overview: tiles, chart, loops, top failing tools, recent runs | Home: status banner, Needs attention, tiles with change vs previous period, runs over time, agents |
| Trace: header facts, waterfall, step panel | Run details: plain-language summary with step links, where the time went, facts, waterfall, step panel (the root-cause step is selected by default) |

`/connect` and `/keys` redirect to their new places.

## Visual system

- **Logo:** three staggered white bars on an indigo (`#4c56d8`) tile, like a trace waterfall: the steps of one run, bundled. Wordmark: lowercase “bindle” in Geist 600. `console/components/Logo.tsx`, `console/app/icon.svg` (favicon), `docs/images/logo.svg`.
- **Icons:** one 16px stroke set (`console/components/Icons.tsx`), always next to a text label: sidebar, page titles, section headings, KPI tiles, Settings tabs, Runs status filter, alert channel types.
- **Dark theme (Midnight):** navy in three depths (page `#0a0f1e` < sidebar `#0d1326` < card `#111831`), hairline indigo-slate borders, indigo accent: `#8e98ff` for links, focus and current items, `#4c56d8` fill with white text for primary buttons. Type: Geist and Geist Mono.
- **Light theme:** cool white (page `#f7f8fb`, card `#ffffff`), ink `#0a0f1e`, indigo `#4c56d8` for links and buttons.
- **Themes:** light and dark from the reference data-viz palette, following the OS, with a sidebar toggle (saved per browser, applied before first paint).
- **Color roles:** a brand accent for links and actions only; status colors (good, warning, critical) only for state, always with an icon and label; data colors from the categorical palette.
- **Step types** use categorical slots in a fixed order: LLM blue, tool orange, retrieval aqua, decision plum, eval yellow, handoff magenta, agent and other neutral gray. Decision moved from violet to plum (light `#77307c`, dark `#983dbc`) with the indigo rebrand: violet sat on top of the indigo accent (CVD ΔE 0.6 light, 4.6 dark). Plum clears the accent (CVD ΔE 14.8 light, 17.2 dark; normal-vision 17.5 / 21.3) and every other step type (CVD ≥ 8.1, normal-vision ≥ 15). Validated with the dataviz validator in both themes (adjacent CVD ΔE ≥ 9.2, normal-vision ΔE ≥ 19.3). Light-mode contrast for three slots is below 3:1, so every step also prints its type label.
- **Charts:** the runs chart stacks OK runs (series blue) under failed runs (critical red, also marked ✕), with hover details and a table view.
