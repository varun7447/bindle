Features

Debug, evaluate and control your agents — in one place.

Every capability below works from the same trace your agent already sends. Filter by what you're trying to do.

Debug

Home: what needs attention

Home answers “is anything wrong?” in one line, then ranks what needs attention, most severe first. Key numbers compare with the previous period, and every metric has a plain-language definition behind its ?.

Repeated step failures grouped with each distinct error
Failure-rate spikes, runaway loops, unusually expensive runs
Agents spending budget on runs that didn’t succeed; unpriced models

Answers cut off at the output token limit; prompts grown too large

Debug

Sessions, feedback and search

Sessions group a conversation’s runs into a chat view with how it ended and what the user said. Home flags conversations where users were unhappy. Search finds runs by what was said, what a tool returned, or the error.

Thumbs and ratings via bindle.feedback()
Full-text search with highlighted snippets
Redacted values stay redacted in search
Python 
bindle.set_session("conversation-42")
trace_id = bindle.current_trace_id()

# later, from your UI
bindle.feedback(trace_id=trace_id,
                thumbs_up=False,
                comment="wrong order")

Works for SDK tools, MCP tools and AgentCore Gateway tools alike
“What users ask about”: new and rising topics, via OpenSearch word statistics — not a model

Security

Security signals

Flags steps worth a second look, on Home, in the run summary and as a badge on the step — each with a plain explanation. A Security signal alert rule notifies your channels.

Possible prompt injection: instructions to ignore rules, reveal the system prompt, chat control tokens, invisible text
Credentials surfacing in a result — redacted before storage, only a count kept
Possible exfiltration: very long URL queries, encoded blobs, sensitive data to messaging tools
Signals 
⚠ Possible prompt injection
  A retrieved document tells the model to
  ignore its instructions.

⚠ Credential in tool result (redacted)

Detectors are deliberately conservative:
signals to review, not verdicts.
Tracing

Linked runs across queues, approvals, handoffs and MCP

Connect work that doesn’t fit in one trace: a run that waits in a queue or for a human’s approval, hands over to another agent, or calls tools on an MCP server. The run page lists what it continued from, continued in, or handed off to.

Store context_token() with the job; resume(token) wherever it continues
MCP calls carry the trace in params._meta
HTTP calls between agents use the standard traceparent header
Python 
token = bindle.context_token()   # store with the job

# hours later, in another service
with bindle.resume(token, name="after approval"):
    ...

# another agent takes over
with bindle.resume(token, kind="handoff"): ...

# MCP client / server
params = bindle.inject_mcp_meta(params)
with bindle.mcp_server_context(params): ...
Evaluate

Evals without calling a model

Deterministic checks run on datasets saved from runs and on a sample of each version’s recent runs. Model-graded scores run in your own environment and come back with bindle.score(). Bindle never holds your model keys.

Output contains / matches, valid JSON, tool (not) called, at most N steps, cost limit, no step failed
bindle eval fails the pull request when the pass rate drops
OpenTelemetry gen_ai.evaluation.result events from Azure AI Foundry, Vertex AI, AgentCore
GitHub Actions 
bindle eval \
  --dataset evals/refunds.jsonl \
  --checks evals/bindle-checks.json \
  --agent my_app.agent:answer \
  --judge my_app.judge:grade \
  --max-drop 0.05 \
  --report eval-report.md
Evaluate

Production problems become eval cases

From a failure group on Home, disliked conversations, failed scores or an agent’s failed runs, one click copies up to 50 recent matching runs into a dataset. Bindle proposes checks that would have caught them and saves only the ones you keep.

Each item labelled with where it came from
Shows how many of the runs each proposed check fails
Datasets outlive trace retention

Evaluate

Replay and recorded-tool cassettes

Replay re-runs one captured LLM call with an edited prompt or another model, side by side with the original. Cassettes save a run’s input and every tool call so you can re-run your agent on a real failure without touching live systems.

Provider key pasted per request, never stored
cassette.report() shows where the new run took a different path
Python Cassette and TypeScript Cassette
Python 
cassette = bindle.Cassette.load(
    "run-0af7….cassette.json")

@cassette.tool
def lookup_order(order_id: str) -> dict: ...

answer = my_agent(cassette.input)
print(cassette.report())
Control

Agent limits and budgets

Pause an agent, cap steps or tokens per run, stop a run that repeats the same tool call (a loop guard), set a daily budget, or Stop run from the console. Limits take effect only where your agent calls check_limits() — Bindle never stops an agent anywhere else.

Settings refresh about once a minute
Budgets use priced spend since 00:00 UTC and notify once a day
LimitExceeded.reason tells you exactly why
Python 
while not done:
    bindle.check_limits()
    step()

# LimitExceeded.reason:
#   paused | over_budget | stopped
#   max_steps_per_run | max_tokens_per_run
#   max_repeat_calls
Cost

Outcome economics

Answers “what does one good result cost?”. The Agents page shows each version’s cost per successful outcome and its wasted spend on failed runs and failed outcomes.

Send outcomes inside a run or later, from elsewhere
Fallback definition: no failed step and no thumbs-down
Amounts with unpriced calls are shown as lower bounds
Python 
bindle.outcome("ticket_resolved")

bindle.outcome("refund_issued",
               success=False,
               trace_id=trace_id)
Cost

Honest cost

Cost comes from published list prices in backend/pricing.json (Anthropic and OpenAI, each with source and date, including long-prompt tiers), or from what your workspace actually pays. A weekly job checks the providers’ pricing pages and opens an issue on change.

Workspace prices for discounts, batch, Bedrock, Vertex, Azure or self-hosted
AWS public Bedrock list prices per region to copy from
Computed on arrival — price changes never rewrite history
Model prices
